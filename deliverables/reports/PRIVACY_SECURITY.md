# Pawverio privacy and security source review

Review date: 4 November 2026. Scope: first-party Android sources in `app/`, `core/`, and `platform/`, dependency declarations, and the generated debug merged manifest available during this review. This is a source-based control checklist, not a penetration test, comprehensive dependency audit, cryptographic certification, legal assessment, or production approval. The parent build/test reports determine release acceptance. Runtime checks not evidenced here remain **NOT TESTED**.

Final evidence update: actual XML verifies **178 core JVM tests PASS, 13 core physical Fire repository tests PASS, and 10 platform physical Fire tests PASS**, with zero failures/errors/skips in those suites. Copied core XML is under `deliverables/android/build-logs/core-tests/` and `core-device-tests/`. The platform suite includes a passing test that explicit deletion removes persisted WorkManager entries, generation fingerprints and active notifications. This does not establish untested lock UI flows, live multilingual voice, Amazon purchase success, or comprehensive security.

## Data and trust boundaries

Pawverio stores pet profiles, optional microchip and allergy information, care tasks/history, veterinarian contacts, medication/vaccine entries, weight entries, and household members in the local Room database. Sitter instructions and emergency contact text use local DataStore. Photos and imported documents use the application's private `files/attachments` directory. Reminder titles and pet/provider names also enter WorkManager's local database and Android notifications. Amazon account identifiers and the cached Premium flag use private SharedPreferences.

No first-party pet-record HTTP client, cloud sync, account registration, GPS, advertising SDK, or analytics integration was found in the reviewed modules. The available debug merged manifest has **no INTERNET permission**. It does include network-state and boot/wake permissions contributed by scheduling libraries. This is source/manifest evidence, not captured network-traffic evidence. Amazon purchases can involve network activity in Amazon's installed store process. Device recognition and text-to-speech services are separate trust boundaries and may process audio or spoken text under provider terms. Consequently, do not describe all voice processing as offline or all data processing as confined to the app process.

## Backup and export limitations

Portable JSON backup contains the six core entity tables. It does **not** contain photos, document bytes, app settings, sitter/emergency preferences, purchase receipts/entitlements, or system credentials. The UI explicitly says photos/documents are excluded. New imported records have no media paths; matching existing records retain their existing local media references. Restore merges by ID rather than replacing all current data. Users need a separate copy of documents/photos and any instructions they wish to preserve. A forgotten backup password cannot be recovered.

Raw JSON, text, PDF, and attachment exports are not password-encrypted. Sensitive confirmation precedes destination selection, but SAF providers can represent local or remote storage. Choosing such a destination authorizes that provider to receive the file. Deleting app records cannot delete external files or copies created by other apps. Document import stores bytes without diagnosing contents; the app does not claim file-format safety against malicious external viewers.

## Findings resolved in final source and remaining limits

1. **Optional lock recovery — source fix present:** `DeviceLock.enabled` now requires both the saved preference and `KeyguardManager.isDeviceSecure`. Removing the device credential therefore stops an unavailable lock from trapping the user. Full enable/background/unlock/credential-removal UI testing remains NOT TESTED; no protection is claimed when device credentials are unavailable.
2. **Immediate screenshot protection — source fix present:** The Settings switch unwraps its Activity context and immediately updates FLAG_SECURE; MainActivity also applies it on resume. Screenshot/recents behavior across supported devices still needs UI evidence.
3. **Scheduling payload deletion — PASS for tested behavior:** `ReminderScheduler.deleteAllData()` clears generation/fingerprint preferences, cancels active notifications, awaits `cancelAllWork()`, and awaits `pruneWork()`. `deletingAppReminderDataClearsPersistedWorkAndGenerationFingerprints` passed on the physical Fire: the unique WorkSpec query became empty, generation preferences were empty, and no active notifications remained. This is logical deletion, not certified erasure of SQL free pages or flash media. Billing entitlement identifiers remain separate for purchase restoration.
4. **Speech disclosure — source fix present:** The privacy notice in the default resources and all 19 app locale resource directories now covers recognition and text-to-speech processing of audio and text, including records chosen for read-aloud. Translation presence is not human language review. Voice-service traffic and installed-engine behavior remain limited by the compatibility evidence; no universal/offline voice claim is made.
5. **Import interruption — remaining maintenance limitation:** Normal editor cancellation/replacement cleanup exists, but process death between copying a private file and saving its entity can leave an orphan. A constrained startup maintenance pass can remove unreferenced private files after allowing for active imports. This does not create an external upload path, but interrupted-import cleanup is not verified.

The first four earlier findings have been addressed in source, with direct physical evidence for scheduling-data deletion. Source fixes alone are not marked runtime PASS. Remaining release limitations include interrupted-import cleanup, complete lock UI testing, vendor speech-service behavior and Amazon verification.

## Amazon verification and release requirements

The implementation requires an app-specific `AppstoreAuthenticationKey.pem` before connecting to vendor authentication. This is a public verification asset, not a production secret. The store-provided localized price is used; no test price grants a purchase. The SKU is `pawverio.premium.lifetime`. Restore checks store account identity and refreshes receipts; store failures preserve an existing offline cache.

There is **no backend receipt verification service** in this offline-first project. Client-side matching does not substitute for Amazon server-side receipt verification. Provision an appropriate verification service if required for the commercial release threat model, keep its vendor secret server-side, and avoid uploading pet-care records with purchase requests. Amazon product setup, receipt validation policy, cancellation/revocation handling, tester accounts and real sandbox/App Tester results remain **BLOCKED** or **NOT TESTED** until their dependencies and evidence are supplied. No Google Play Billing integration is used in the reviewed Amazon build.

Before release: inspect the final signed release manifest/APK; perform device lock and deletion tests including WorkManager data; verify attachment cancellation/replacement and interrupted imports; verify sensitive exports and backup round-trip/tamper/password handling on supported devices; test speech permission denial, missing engines, and background cancellation; complete Amazon purchasing/restore testing and receipt-verification decisions; review third-party SDK privacy disclosures and dependencies; finish the privacy policy with an actual publisher identity/support contact and applicable specialist review. This document makes no GDPR, UK GDPR, store-policy, or other legal compliance assertion.
